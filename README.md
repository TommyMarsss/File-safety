# 安全文件上传服务

纯 Python 标准库后端 + 原生 HTML/CSS/JS 前端的文件上传服务，重点演示三类服务端安全校验：**魔数识别、路径穿越防御、ZIP 压缩炸弹检测**。

## 运行

```bash
python3 server.py          # 默认 http://127.0.0.1:8000
python3 server.py 9000     # 指定端口
```

打开浏览器访问首页，可直接选择文件上传，或点击预置样本按钮（合法 PNG / 合法 ZIP / 伪造 .png 的 EXE / 路径穿越文件名 / ZIP 炸弹 / 含符号链接的 ZIP / 含 `../` 条目的 ZIP）。样本按钮会从 `/samples/<name>` 取回样本字节，再以**真实 multipart/form-data** POST 到 `/upload`，页面实时展示后端的接受/拒绝判定与原因。

## 测试

```bash
python3 -m unittest tests.test_upload -v
```

覆盖：合法 PNG/ZIP 上传、魔数不匹配拒绝、扩展名与真实类型不一致拒绝、`../` / 绝对路径 / Windows 反斜杠路径文件名拒绝、ZIP 炸弹在检测阶段拒绝（拒绝后服务仍健康）、符号链接 ZIP 拒绝、嵌套 ZIP 炸弹拒绝。

## 校验策略

### 1. 魔数识别（`filecheck.detect_type`）

只认文件头字节，不认用户提交的扩展名和 Content-Type：

| 类型 | 魔数 |
|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| JPEG | `FF D8 FF` |
| GIF | `GIF87a` / `GIF89a` |
| BMP | `BM` |
| WebP | `RIFF....WEBP` |
| PDF | `%PDF-` |
| ZIP | `PK\x03\x04` / `PK\x05\x06` |

无法识别的一律拒绝（因此 MZ 可执行文件即使改名 `.png` 也会被拒）。识别成功后还要求**扩展名与真实类型一致**（`check_extension`），防止「真 PNG 伪装 .gif」这类混淆。存储文件名由服务端用 UUID 生成（`uploads/<uuid>.<真实类型扩展名>`），用户输入完全不影响存储路径。

### 2. 路径穿越防御（`filecheck.sanitize_filename`）

策略是**拒绝而非静默改写**，让攻击尝试可见：

- 含 `/` 或 `\` 的任何文件名（包括 `../`、`./`、子目录、Windows 反斜杠变体）一律拒绝；
- 绝对路径（`/...`、`C:...`）拒绝；
- NUL 字节、空名、`.`、`..`、超长名拒绝。

ZIP 条目名做同样检查（`_check_entry_name`），解压时再用 `safe_join` 做纵深防御：`realpath` 解析后目标必须仍落在解压目录内。

### 3. ZIP 炸弹检测（`filecheck.validate_zip`）

**所有检查在写盘/解压前完成**，只读中央目录元数据和受预算约束的嵌套内容：

- 单条目压缩比 > 100:1 → 拒绝（压缩炸弹的典型特征，测试样本约 1000:1）；
- 解压后总大小（含嵌套累计）> 32MB → 拒绝；
- 条目数 > 512 → 拒绝（防 zip 目录洪泛）；
- 符号链接条目（`external_attr` 高 16 位为 `S_IFLNK`）→ 拒绝；
- 条目名含 `../` 或绝对路径 → 拒绝（zip-slip）；
- 加密条目 → 拒绝（无法检查内容，不接受黑盒）；
- 嵌套 ZIP 递归检查，层数 > 2 → 拒绝（防递归炸弹/quine 类构造）。

### 4. 其他

- 单次上传原始字节上限 64MB（HTTP 层 413）；
- 上传目录可用环境变量 `UPLOAD_DIR` 覆盖。

## 已知局限

- **multipart 解析器是极简实现**：整个请求体读入内存后按 boundary 切分（有 64MB 上限兜底）；filename 中含未转义引号等畸形构造可能解析失败（失败即拒绝，不会误判为合法）。生产环境应使用流式解析器。
- **魔数只覆盖常见类型**：文本文件（无魔数）无法识别，默认拒绝；如需支持需另加可打印字符启发式。
- **魔数不等于内容安全**：检查只验证「文件声称的类型是真的」，不验证「文件内容无害」。例如一个真实 PNG 仍可能携带针对图片解析器漏洞的 payload；PDF 可内嵌 JavaScript。深度内容清洗（如图片重编码）不在本项目范围。
- **压缩比阈值是启发式**：某些高度可压缩的合法文件（如超大稀疏日志的 zip）可能误伤，可按业务调整 `MAX_ZIP_RATIO`。
- **TOCTOU**：解压前的元数据检查与实际解压之间存在理论上的时间差，但 zip 字节已在内存中固定，攻击者无法在两次读取间改变内容，因此本场景不构成实际风险。
- 未实现鉴权、速率限制、病毒扫描；仅监听 `127.0.0.1`，不要直接暴露到公网。

## 项目结构

```
filecheck.py          安全校验核心（魔数/文件名/ZIP）
server.py             HTTP 服务、multipart 解析、样本生成、上传处理
static/index.html     前端页面（原生 JS，FormData 真实上传）
tests/test_upload.py  端到端测试（真实 HTTP multipart 请求）
uploads/              上传存储目录（运行时创建）
```
